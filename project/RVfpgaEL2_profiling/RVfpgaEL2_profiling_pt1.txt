  throw_std_bad_alloc() is called every single run, meaning the Eigen dynamic
  matrix constructor is failing to allocate heap memory. The program then hits
  an assert and exits before reaching the Kalman filter computation. This is why
   the timing columns are all -nan and there are no entries for any
  filter/solver functions — they never execute.

  Root cause: The bare-metal heap (_sbrk) likely runs out or is too small for
  the dynamic Eigen matrices (Matrix<double, -1, -1> uses heap allocation). The
  3 matrix allocations per run all fail on the third one.

  _sbrk (heap allocation), but the program never gets further than constructing
  2–3 dynamic matrices before aborting. You'll want to either:
  1. Increase the heap size in the linker script, or
  2. Switch to fixed-size Eigen matrices (Matrix<double, N, N> with compile-time
   dimensions) to avoid heap allocation entirely
