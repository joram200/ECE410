     Context

     The existing project/new_hdl/ directory has a working multi-file Option B

     scripts. M3 requires a project/m3/ submission that:

     files)
     - Replaces OpenLane 2 synthesis with Vivado OOC synthesis + XDC constraints
      file
     - Produces all M3 checklist deliverables (simulation log with PASS,
     annotated waveform, synthesis reports)
     - Has a run_m3.sh orchestration script adapted from
     project/new_hdl/run_m3.sh

     Source truth for existing modules: project/new_hdl/rtl/ and
     project/new_hdl/tb/

     3. project/m3/synth/constraints.xdc

     Vivado Design Constraints file — replaces config.json (OpenLane 2):
     # constraints.xdc — Vivado timing constraints for 'top' (Option B Kalman
     accelerator)
     # Target: Artix-7 100T (xc7a100tcsg324-1), 100 MHz

     set_input_delay  -clock clk -max 2.0 [all_inputs]

     4. project/m3/synth/run_ooc.tcl

     Non-project mode OOC synthesis. Reads from rtl/top.sv only (single-file, no
      separate files needed). Reports go to synth/ (not reports/):
     set base [pwd]
     read_verilog -sv "$base/rtl/top.sv"
     synth_design -top top -mode out_of_context -part xc7a100tcsg324-1
     create_clock -period 10.000 -name clk [get_ports clk]
     set_input_delay  2.0 -clock clk [all_inputs]
     set_output_delay 2.0 -clock clk [all_outputs]
     report_utilization    -file "$base/synth/area_report.txt"
     report_timing_summary -file "$base/synth/timing_report.txt"
     report_power          -file "$base/synth/power_report.txt"
     puts "INFO: OOC synthesis complete."

     5. project/m3/synth/gtkwave_export.tcl

     GTKWave Tcl script to produce an annotated PNG from the VCD. Loads AXI
     write signals, core busy/done, AXI read signals; adds three comment markers
      for host-write, compute, host-read regions:
     set dumpfile [lindex $argv 0]
     set outfile  [lindex $argv 1]
     gtkwave::loadFile $dumpfile
     # Add signals: m_awvalid, m_awready, m_wvalid, core_start, core_busy, 
     core_done, m_arvalid, m_rdata
     # Add region markers
     gtkwave::setZoomFactor -10
     gtkwave::addComment "HOST WRITE (A_REG/B_REG)"
     gtkwave::addComment "KALMAN COMPUTE"
     gtkwave::addComment "HOST READ (C_REG)"
     gtkwave::hardcopy $outfile

     - Only handles Option B (no A vs B comparison)

     7. project/m3/synth/critical_path.md

     One-paragraph writeup identifying the critical path through the F64
     adder/multiplier in the Kalman update datapath. To be written based on the
     timing report output (WNS, start/end points). Template structure:
     - Critical path start: register output of exponent accumulator in f64_mul
     - Critical path end: sign-selection mux input in f64_add
     - Stages: multiply mantissa → exponent check → add alignment shift →
     normalize
     - Why critical: 106-bit product ripples through exponent comparator before
     reaching adder
     - What would shorten it: register the multiplier output (pipeline stage
     between mul and add)
