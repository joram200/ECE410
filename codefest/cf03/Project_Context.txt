● Both files are created. Here's a summary of each:

  ---
  gemm_naive.cu

  - Kernel: gemm_naive — one thread per output element C[row][col]
  - Thread mapping: (blockIdx.y*32 + threadIdx.y, blockIdx.x*32 + threadIdx.x) →
   row/col of C
  - Inner loop: iterates over all k in global memory — no reuse, fully
  unoptimized
  - Launch config: 32×32 thread blocks, 32×32 grid (1024/32 each dimension)

  ---
  gemm_tiled.cu

  - Kernel: gemm_tiled — one thread per output element, but uses shared memory
  - Tile size: 8×8 (TILE_SIZE = 8)
  - Strategy: iterates over numTiles = 1024/8 = 128 strips; each iteration loads
   one 8×8 tile of A and one 8×8 tile of B into __shared__ arrays, syncs,
  computes partial dot product, syncs again
  - Boundary guards: 0.0f padding handles non-multiples (not needed for 1024,
  but correct in general)
  - Launch config: 8×8 thread blocks, 128×128 grid

  ---
  To compile:
  nvcc -O2 -o gemm_naive codefest/cf03/cuda/gemm_naive.cu
  nvcc -O2 -o gemm_tiled codefest/cf03/cuda/gemm_tiled.cu

  Both include a main() that initializes A=B=1 (so every C element should equal
  1024), runs the kernel, and prints PASS/FAIL.

● The NVIDIA kernel module was never built for kernel 6.19.11-arch1-1. This is a
   DKMS rebuild issue — the driver exists but wasn't compiled against the
  running kernel. Run these to diagnose:

  # See what NVIDIA packages are installed
  pacman -Q | grep -i nvidia

  # See what DKMS modules are registered and their build status
  dkms status

  The most likely fix:

  # Reinstall the DKMS driver — triggers a rebuild against the current kernel
  sudo pacman -S nvidia-dkms linux-headers
  sudo dkms autoinstall
  sudo modprobe nvidia

  If nvidia-dkms isn't the package you have (e.g. you have nvidia instead of
  nvidia-dkms):

  # The non-DKMS package ships pre-built modules tied to a specific kernel
  # You need the version that matches 6.19.11-arch1-1 exactly, or switch to DKMS
  sudo pacman -S nvidia-dkms linux-headers

  Root cause: Arch's standard nvidia package ships pre-built .ko files for one
  specific kernel. When the kernel updates, the module directory changes
  (/lib/modules/<new-kernel>/) and the old .ko is no longer found. nvidia-dkms
  solves this by recompiling the module automatically on every kernel update via
   a pacman hook.

● "No such device" means the module built fine but can't find the hardware. On a
   laptop with an RTX 3070 Mobile this almost always means the dGPU is powered
  off or hidden from the OS. Check:

  # Does the OS even see the NVIDIA GPU on the PCIe bus?
  lspci | grep -i nvidia

  mokutil --sb-state

  If lspci shows nothing for NVIDIA: the dGPU is disabled at the BIOS/firmware
  level. Reboot into BIOS and look for a setting like:
  - Graphics Mode → change from iGPU Only / UMA Only to Discrete or Hybrid
  - dGPU → Enabled
