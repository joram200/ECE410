● Answer: ~109 GFLOP/s theoretical, ~87 GFLOP/s practical.

  Here's why:

  Why tiling lands at the L1 ceiling, not peak compute:

  For 3×3 matrices, a "tile" IS the full matrix — the entire update() dataset
  (496 B) fits in a few L1 cache lines. A register-blocked tiled GEMM would:
  - Load each persistent matrix once from L1
  - Hold all intermediates in AVX registers across all 18 sub-operations
  - Write only final outputs back

  This achieves the ideal AI = 0.4637 FLOPs/byte, bounded by L1 bandwidth (235
  GB/s practical).

● Required bandwidth = 473.93 Mupdates/s × 496 B = 235.1 GB/s

  Using the formula BW = Throughput × Data Width:

  ┌────────────────────────────────────┬──────────────────────────────────┐
  │                Term                │              Value               │
  ├────────────────────────────────────┼──────────────────────────────────┤
  │ Throughput                         │ 1 / 2.11 ns = 473.93 M updates/s │
  ├────────────────────────────────────┼──────────────────────────────────┤
  │ Data width (unique tensors, ideal) │ 496 B/update                     │
  ├────────────────────────────────────┼──────────────────────────────────┤
  │ Required bandwidth                 │ 235.1 GB/s                       │
  └────────────────────────────────────┴──────────────────────────────────┘

  The reads break down as: A (216 B, loaded 3×) + C (120 B, loaded 5×) + Q, R,
  I, dt, x_hat, P, y, t = 608 B reads; plus 128 B writes — but counting each
  unique tensor once (the AI basis) gives 496 B, which is the tighter bound used
   here.

  This number is self-consistent: the tiled GEMM estimate was derived assuming
  235 GB/s L1 bandwidth, so multiplying throughput back by data width recovers
  that same bandwidth — confirming the kernel is exactly at the L1 ceiling. DRAM
   (41 GB/s) is 5.7× too slow to sustain this throughput, which is why tiling is
   mandatory for the kernel to be viable at this rate.
